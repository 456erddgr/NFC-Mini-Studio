# 常见问题（FAQ）

---

## 安装与启动

### Q：双击安装程序没反应？

onefile 打包的 exe 启动时要把自己解压到临时目录，第一次会慢 **2~5 秒**。等一等。

如果超过 10 秒还没出现窗口：

1. 右键 → 属性 → 检查文件大小是否完整（应该 130 MB 以上）
2. 杀毒软件可能拦了，加到白名单
3. 换绿色版 `dist\NFC Mini Studio\NFC Mini Studio.exe` 试

### Q：装完打开是白屏 / 一片黑？

窗口是 pywebview 承载的网页。白屏通常是前端资源没打进去。

排查：

```powershell
python run.py --selftest
```

看「资源路径解析」那项。如果 `frozen=True` 但资源找不到，说明 PyInstaller 漏了 `--add-data "app/web;app/web"`。

重新用 `python build_all.py app` 打包。

### Q：需要管理员权限吗？

**不需要**。

- 安装程序全部写在 `HKCU` 和 `%LOCALAPPDATA%`
- 程序运行时只用蓝牙和本地文件
- 数据在 `%APPDATA%\NFCMiniStudio`

唯一需要管理员的地方是**启动 PC/SC 服务**（`net start SCardSvr`），那是一次性的系统设置。

### Q：数据存在哪？卸载会删吗？

```
%APPDATA%\NFCMiniStudio\
├── settings.json          设置
├── cards.json             卡夹
├── keybox.json            密钥库
├── crack_cache.json       破解缓存
├── selftest_report.txt    自检报告
└── wallpapers\            用户壁纸
```

卸载程序**不会**删这个目录（保护你的卡夹数据）。想彻底清干净就手动删。

### Q：能装在 U 盘里带走吗？

绿色版可以：把 `dist\NFC Mini Studio\` 整个拷到 U 盘，插哪台电脑都能跑（Windows 10+）。

但**卡片存档不会跟着走**（在 `%APPDATA%`）。想带走就把 `%APPDATA%\NFCMiniStudio` 一起拷。

## 蓝牙原厂读卡器

### Q：扫不到读卡器？

按顺序排查：

1. **读卡器开机了吗**：指示灯应该闪
2. **有电吗**：插上充电，等 30 秒
3. **蓝牙被占用了吗**：这是最常见的原因 —— **手机微信里的小程序必须退出**。小程序连着读卡器时，电脑连不上。
   - 微信 → 下拉 → 长按小程序卡片 → 关闭
   - 或者干脆把手机蓝牙关掉
4. **距离**：1 米内，避开 USB 3.0 接口（USB 3.0 会干扰 2.4 GHz）
5. **系统蓝牙开了吗**：Windows 设置 → 蓝牙和其他设备

### Q：能连上但一用就断？

电池电量低。插上充电，或者充 10 分钟后再试。

设备页会显示电量，低于 20% 建议充电。

### Q：换台电脑还用重新配对吗？

不用。BLE 不需要配对，扫描到就能连。

### Q：读卡器能同时连手机和电脑吗？

**不能**。BLE 从设备同一时间只能被一个中心连。

这就是为什么用电脑时要把小程序关掉。

## 通用 PC/SC 读卡器

### Q：提示「PC/SC 服务未启动」？

Windows 的 Smart Card 服务默认是手动启动且没启动。在**管理员 PowerShell** 里：

```powershell
sc config SCardSvr start= auto
net start SCardSvr
```

软件里的「检测 PC/SC 环境」按钮旁边有「复制修复命令」，可以一键复制上面两行。

### Q：服务启动了但还是扫不到读卡器？

1. **读卡器插好了吗**：设备管理器 → 「智能卡读卡器」分类下应该有你的型号
2. **驱动装了吗**：ACR122U 等主流型号免驱；有些杂牌需要装厂家驱动
3. **USB 口换一个**：有些前置 USB 口供电不足
4. **是不是 PC/SC 读卡器**：有些廉价的「读卡器」其实是串口模块（CH340/CP2102），不是 PC/SC 标准设备，用不了这个通道

### Q：读卡器亮灯但读不到卡？

1. 卡片贴准感应区（读卡器上一般有 NFC 图标）
2. 卡片类型对不对：这个通道只支持 **13.56 MHz**（Mifare / NFC）。125 kHz 的低频 ID 卡读不了。
3. 试试别的卡，排除是卡坏了

### Q：为什么 PC/SC 通道不能破解？

因为破解需要**采集认证过程的随机数**，这要靠原厂固件在 BLE 协议里回传。PC/SC 标准 APDU 里没有这个能力——读卡器固件根本不会把随机数暴露给上位机。

这是硬限制，不是软件能绕过的。

### Q：为什么 PC/SC 通道不能读 ID 卡？

PC/SC 标准是 13.56 MHz（ISO14443 / ISO7816）。125 kHz 低频卡完全不兼容，硬件层面就没有天线。

原厂读卡器是双频的（13.56 MHz + 125 kHz），所以能读。

## 手机读卡器

### Q：APK 装不上？

1. **允许未知来源**：设置 → 安全 → 未知来源（或「安装未知应用」→ 浏览器/文件管理器 → 允许）
2. **Android 版本**：需要 Android 5.0+（minSdk 21）
3. **存储空间**：APK 4.1 MB，装完约 8 MB
4. **解析包错误**：文件下载不完整，重新传一遍（可以用数据线、微信文件传输助手、网盘）

### Q：提示「设备不支持 NFC」？

这个手机没有 NFC 硬件，或者 NFC 坏了。

查手机参数：设置 → 关于手机 → 看有没有「NFC」；或者在系统设置里搜「NFC」。

绝大多数中高端 Android 机都有 NFC，但**很多千元机没有**。

### Q：电脑搜不到手机？

按顺序排查（**这是最常见的问题**）：

1. **同一个 Wi-Fi 吗**：电脑和手机必须在同一网段。电脑上 `ipconfig` 看是不是 `192.168.1.x`，手机上 App 显示的是不是也是 `192.168.1.x`。
2. **AP 隔离**：很多路由器默认开「AP 隔离 / 客户端隔离 / 访客网络隔离」，会让同一 Wi-Fi 的设备互相看不见。
   - 进路由器后台（通常 `192.168.1.1`）→ 无线设置 → 关掉「AP 隔离」
3. **Windows 防火墙**：第一次连接时会弹窗，选「允许访问」。如果当时点了「取消」，去防火墙设置里手动放行。
4. **手机 App 里服务没启动**：看 App 上「运行状态」是不是绿色。手动按一次「启动读卡服务」。
5. **手机切过 Wi-Fi**：IP 变了。重新在电脑上点「搜索手机读卡器」。

**最快的验证方法**：电脑浏览器打开 `http://手机IP:8765`。如果连不上，说明网络层就不通，跟软件无关。

### Q：能连上但寻卡一直失败？

手机 NFC 的感应范围**极小**（1~3 cm），而且位置挑剔：

1. **找准天线位置**：一般在手机背面**上半部分**、摄像头附近。不同机型不一样，可以查手机说明书或网上搜「XX 手机 NFC 位置」。
2. **贴紧**：卡片要完全贴住手机背面，不能有缝隙。
3. **别动**：读整卡时手要保持静止，一动就断。
4. **卡片方向**：有些卡需要正对，翻面试试。
5. **手机壳**：太厚的手机壳（尤其带金属或磁吸的）会屏蔽 NFC，摘掉试试。

### Q：手机读卡器能破解吗？

不能。手机 NFC API 不提供随机数采集能力。

寻卡、读块、写块、写 UID、整卡导出都可以。

### Q：手机读卡器耗电吗？

NFC 读卡模式 + TCP 服务大约 **5~10% 每小时**。长时间用建议插着充电。

App 会让屏幕常亮，所以更费电。不用时记得关掉 App。

## 读卡与写卡

### Q：读卡一直「认证失败」？

说明密钥不对。按顺序检查：

1. **卡是不是全加密的**：试试默认密钥 `FFFFFFFFFFFF` 能不能通
2. **先破解**：全加密卡必须先破解才能读
3. **密钥库里有没有**：看看「密钥库」页有没有这把卡的密钥
4. **是不是 IC 卡**：如果是 ID 卡（125 kHz），需要原厂读卡器 + 「读 ID 卡」功能
5. **扇区权限位**：有些卡虽然密钥对，但扇区尾块设了「永不可读」，读出来是固定的假数据

### Q：读出来的数据全是 0？

两种情况：

1. **密钥错了但软件没报错** —— 老版本有这个问题，v2.6.0 已修。当前版本应该明确报「密钥认证失败」。
2. **这个块确实是空的** —— 新卡未写入的块确实是全 0。

### Q：写块失败？

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| 密钥认证失败 | 密钥不对 | 先破解 / 换密钥 |
| IC 写卡失败 | 卡片写保护 / 权限位不允许 | 检查扇区尾块访问位 |
| 参数超出范围 | 块号越界 | 1K 卡是 0~63，4K 卡是 0~255 |
| 写后校验不一致 | 卡是只读卡（如普通 IC 卡写 0 块） | 换 UID 卡 |

### Q：写卡写坏了怎么办？

如果之前「读取整卡」保存到卡夹了：

1. 卡夹 → 选那张卡 → 「写入到卡片」
2. 软件会逐块写回去

**没备份的话，重要扇区（含密钥和权限位）写错可能永久锁死，救不回来。**

这就是为什么软件反复提示「写卡前先备份」。

### Q：能复制门禁卡吗？

分情况：

- **卡能读出来** → 能。写到 UID 卡里，UID 和扇区内容都能复制。
- **卡能破解** → 能。先破解再读再写。
- **全加密 + 破不出来** → 不能。
- **CPU 卡（金融 IC 卡、银行卡）** → 不能。这类卡有硬件加密协处理器，不是 Mifare Classic。
- **有滚动码 / 服务器验证的系统** → 复制了也用不了。门禁服务器会校验动态码。

### Q：为什么写 UID 后卡不能用了？

可能原因：

1. **BCC 算错了** —— 软件应该自动算，除非你手动构造了块 0
2. **SAK / ATQA 设错了** —— 软件用 `08` / `04 00`，某些系统需要别的值
3. **卡不是真 UID 卡** —— 普通 Mifare Classic 的 0 块是出厂 OTP 写保护的，硬写会导致卡异常

### Q：读整卡很慢？

正常。1K 卡有 64 个块，每块都要认证 + 读，加上 BLE 的延迟，一张卡 20~40 秒。

提速方法：

- 用「极速」模式
- 减少重试次数（设置里）
- 如果只是看 UID，用「寻卡」而不是「读整卡」

## 破解

### Q：mfkey32 和 HardNested 有什么区别？

| 方法 | 适用 | 速度 | 原理 |
| --- | --- | --- | --- |
| mfkey32 | 能采到随机数的卡 | 秒级 | 利用错误认证时卡片吐出的 nt |
| HardNested | 全加密卡（不吐 nt） | 几分钟~几小时 | 统计大量 nonce 对反推 |

先试 mfkey32，不行再 HardNested。

### Q：设备端破解和软件端破解选哪个？

| | 设备端 | 软件端 |
| --- | --- | --- |
| 速度 | 快（固件优化） | 慢（PC 穷举） |
| 通道 | 仅蓝牙原厂 | 全部 |
| 需要抓包 | 不需要 | mfkey32 需要 |

有原厂读卡器就用设备端。

### Q：破解跑了很久没结果？

1. **卡片是不是在感应区**：采集阶段需要卡一直贴着
2. **HardNested 本来就慢**：搜索空间大，可能要跑几小时
3. **是不是 CPU 卡**：CPU 卡用这整个方法体系都无效
4. **换设备端破解**：如果原厂读卡器支持

### Q：云端 keygen 安全吗？

云端功能是**可选**的，不配置完全不影响使用。

配置后会把卡 UID 和采集到的 nonce 发到原厂服务器查询密钥库。如果你在意隐私，就只用本地破解。

## 三条通道的差异

### Q：到底该用哪个通道？

```
有原厂 NFC Mini 读卡器？
├── 有 → 用蓝牙通道（能力最全）
└── 没有
    ├── 有 PC/SC 通用读卡器？ → 用 PC/SC 通道
    └── 都没有，但手机有 NFC？ → 用手机读卡器
```

### Q：能力对比

| 功能 | 蓝牙原厂 | 通用 PC/SC | 手机读卡器 |
| --- | :-: | :-: | :-: |
| 寻卡 / 读 UID | ✅ | ✅ | ✅ |
| 读块 | ✅ | ✅ | ✅ |
| 写块 | ✅ | ✅ | ✅ |
| 整卡导出 | ✅ | ✅ | ✅ |
| 写 UID | ✅ | ✅ | ✅ |
| 写卡号 | ✅ | ⚠️ 看卡 | ⚠️ 看卡 |
| 密钥校验 | ✅ | ✅ | ✅ |
| 设备端破解 | ✅ | ❌ | ❌ |
| 读 125 kHz ID 卡 | ✅ | ❌ | ❌ |
| 封卡 | ✅ | ❌ | ❌ |
| 设备信息/电量 | ✅ | ⚠️ 合成值 | ⚠️ 手机电量 |
| 固件升级 | ✅ | ❌ | ❌ |

### Q：能同时连多个通道吗？

不能。同一时间只能用一个。切换通道会自动断开前一个。

## 其他

### Q：这软件会联网吗？

**默认不联网**。所有功能本地完成。

只有两种情况会联网：

1. 你主动点「获取云端 Token」/ 用云端 keygen
2. 「设置」里开启了自动检查更新（默认关）

### Q：会被杀毒软件报毒吗？

可能。PyInstaller 打包的 exe 经常被误报（因为打包器本身常被恶意软件用）。

处理：

1. 加白名单
2. 或者用源码运行（`python run.py`）—— 这个基本不会报
3. 如果要从源码自己打包，打完的 exe 报毒率会低一些

### Q：源码在哪？能自己改吗？

全在 GitHub 上，MIT 协议，随便改。

结构见 [原理说明](原理说明.md) 的目录结构一节。

### Q：能移植到 Mac / Linux 吗？

理论上可以：

- Python 部分跨平台（`bleak` 支持 macOS/Linux，`pywebview` 支持）
- **PC/SC 部分需要重写**：现在硬编码绑定 `winscard.dll`。macOS 是 `PCSC.framework`，Linux 是 `libpcsclite.so`。接口几乎一样，换个加载方式就行。
- Android APK 本来就跨平台

目前没做，因为主要需求是 Windows。

### Q：怎么贡献代码？

1. Fork
2. 改
3. 跑 `python run.py --selftest` 确保全绿
4. 提 PR，说明改了什么、为什么

### Q：发现 bug 怎么报？

在 GitHub Issues 里提，附上：

- 软件版本（帮助页底部）
- 用的哪个通道（蓝牙 / PC/SC / 手机）
- 读卡器型号 / 手机型号
- 复现步骤
- `%APPDATA%\NFCMiniStudio\selftest_report.txt` 的内容
- 如果能重现，附日志
